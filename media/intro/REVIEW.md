# REVIEW ― context-flow 紹介動画(2026-11-12、1 回目)

## 作った判断
- 採用した筋は A「流れを取り戻す」(STORYLINES.md)。架空の orders-api のセッション(12 ターン済み)に途中からペインを足し、13 ターン目を送ってから要約が届くまでを追う。B(年表だけ)と C(3 時間後)は作っていない。
- 8 場面・99.9 秒:hook / reveal / flow / now / meter / done / jump / end。枠(地・端末窓・左 55% / 右 45%・字幕)は claude-cockpit の動画と同じ。
- 右のペインは絵を並べず、`src/pane.js` が時刻から描く。`context-flow/hooks/register.tsx` の `ui.render`(Pane)の式を移したもので、行の並び・文言・記号・虹・コマの刻み(走っている間 80 ms、待機中 960 ms、要約の直後 3.5 s は 80 ms)・打ち出し 18 ms / 字は実物と同じ。足した表示は無い。
- 全角は 2 桁ぶんの幅にした(20px の字 + 字間 4px)。実物の折り返し(55 桁)と右端の位置が合う。cockpit の動画は全角を詰めているので、ここだけ見た目が違う。
- 「70% で琥珀、85% で赤」は実際に色を変えず、バーの下に目盛りを 2 つ出した(色を変えると、以降ずっと虹のバーが見えなくなるため)。
- reveal の「途中から入れても流れを起こす」は早回し。実物は 2 秒ごとに 1 ターンずつ要約するが、動画では 12 ターンを約 5 秒で打ち出している。
- `/context-flow`(開き直し)はナレーションでは言わず、終わりのカードの文字だけ。

## 測ったこと / 見ただけのこと
- `hyperframes check`:エラー 0(ok: true)。残した警告:`text_below_floor`(端末の文字 20px < 28px。端末のモックなので固定)、`contrast`(薄色 #7f849c on #1e1e2e = 4.44:1。実際の端末の dim と同じ)、`composition_file_too_large`(各 scene に pane.js と会話のデータを inline しているため)、`container_overflow` 1 件(入力欄の上の罫。見た目は収まっている)。
- 見た:snapshot 約 30 枚と、書き出した mp4 から ffmpeg で抜いた 14 枚(全場面)。ペインの文言・記号は register.tsx と突き合わせた。字幕のはみ出しは無い。
- 音は測っただけで聞いていない(mix.wav peak 0.903、声 −16 dBFS RMS)。Kokoro の読み(「コンテキストフロー」「琥珀」など)は耳で確かめていない。
- HyperFrames のプレビュー(Studio)は開いていない。

## 弱いところ
- hook:transcript が 2.6 秒で流れて止まるだけ。「見失う」の実感は弱い。
- now:サブエージェントの結果を待つ間、左の transcript に空行が 2 行続く(結果の行を後から出すための場所)。
- jump:押すのは 1 回(#10)だけ。押した行の色は変わらない(実物も変わらない)。
- 尺 99.9 秒は目安(60〜100 秒)の上限。削るなら flow の 3 つ目の字幕(古い順に上から)。
